# Architecture

Nox starts as a voice room and keeps the resulting scene in that room. It validates model output before physical execution and ties each operation to the current source and experiment.

1. `src/assistant/panel.ts` presents Nox as the initial speaking control. A browser permission gesture starts `src/assistant/voice.ts`; recognition, speech synthesis and optional Keyboard input feed `src/assistant/actions.ts`. Listening, pending work, replies and errors have actual state. Recent conversation is bounded to page memory.
2. Contextual Camera/Add drawing controls and room drop/paste feed `packages/input/src/source` image normalization. `src/input/ui.ts` retains source revisions, notes and clarification answers. `src/input/prompt.ts` requests grounded rigid/compound approximations of unfamiliar subjects, declared estimates and critical-intent questions when needed.
3. The current public route uses `server/openrouter.ts`: one pinned free NVIDIA vision model, native output schema, bounded visual reasoning and zero prompt/completion/image/request price ceilings. Provider/model fallbacks and paid plugins are absent. `NOX_PUBLIC_AI=enabled` explicitly opens only this fixed free provider in `server/vercel.ts`; other/default deployments retain their gate. Public requests still pass same-origin, body/request/schema, cancellation and deadline checks. The assistant has no code-entry UI. An English free-pivot guard catches missing hinges and asks one concrete question, then rejects a still-missing hinge instead of looping.

   `server/middleware.ts` bounds request size/time and chooses server-side providers. `server/cloudflare.ts` calls the fixed official Cloudflare API with Gemma 4 26B A4B; `server/momen.ts` and `server/anthropic.ts` remain separate explicit choices. Credentials never enter the scene or client bundle. The direct adapter sends the real normalized image as an image content part. Trusted server route maps select photo bounding-box or canvas stroke-ID interpretation schemas and the command schema; Cloudflare receives a named strict JSON schema with thinking disabled, while legacy no-schema callers retain JSON-object behavior. The adapter honors cancellation and rejects redirects, refusal, truncation and tool routes. No retry or provider fallback is added. See [current and historical evidence](VERIFICATION.md#bounded-cloudflare-live-workflow).

   The current NVIDIA and historical Momen paths use `server/drawing.ts` for canonical drawing requests: the model emits metric primitive/convex geometry, inline provenance and explicit support references; Nox compiles these to the existing canonical scene. The drawing wrapper includes the trusted schema in its instructions. Support casting uses actual collider shapes and cannot move a joint-connected body's explicit pose. For NVIDIA commands, `server/commands.ts` reuses the same degree conversion and collider seating: a model proposes relative degree rotations and named supports, and Nox compiles canonical rotate/move operations before strict command validation. Other operations, other providers and public request schemas retain their contracts. The historical Momen adapter stays unchanged. Cloudflare remains a separate explicit provider with historical evidence.
4. `src/input/contract.ts` validates proposed canonical 3D scenes and edits, including geometry, units, identity and connection alignment. `src/input/preview.ts` quarantines an unconfirmed scene from the existing experiment.
5. `src/physics` owns scene validation, Rapier execution, version/baseline data, measurements and checkpoint recovery. `src/viewport.ts` renders physical geometry through Three.js. When a scene is available, the room exposes it and docks Nox below. `src/ui/shell.ts` keeps optional Draw, Source, Library, Parts, measurements and workbench controls behind Tools. Presentation transitions follow real state and do not drive physics.

An exact bounded request such as “Create a ramp and ball” constructs new local scene data with a fixed floor, fixed ramp and dynamic ball, then starts the real solver after rendering settles. Its dimensions and contact coefficients are declared defaults. No captured model reply, source image or live inference is involved. Custom details that do not fit the local request must stay on the custom proposal path rather than being dropped.

A photo selection prepares/stages the image, and Nox acknowledges it. An ordinary spoken or typed build request carries that image and the user's intent to interpretation, taking precedence over presets/text-only creation. Missing physical measurements are estimated. A ready requested build passes staged validation before confirmation/run; a genuine critical question waits for an answer. Repeated requests during the build report progress without superseding it. Unbuilt sources remain attached after cancellation/error; confirmed sources stop acting as pending attachments. Captured-response checks remain separate from real inference. Ordinary physical edits produce a readable diff (rotations in degrees), speak a brief reply and wait for yes or Apply. Source/version changes or cancellation invalidate stale results. Stop turns voice off and cancels pending work. Save/reload and export/import retain confirmed work and its source; absent or incompatible checkpoints remain visible recovery states. Earlier provider/automatic-upload acceptance is historical; see the current conversational evidence.

The solver uses SI units, a 1/120 s step and sampled output for plots. It supports rigid bodies, compound/convex geometry, fixed/hinge/slider/spherical/rope/spring connections, finite-effort motors, declared forces/drag and a parameterized fan model. Semantic object names do not select behavior: characters, scenery and abstract forms require actual allowed geometry. Fluid flow, electricity and deformation are outside the solver; rigid proxies and their limits must be explicit. Published bounds and source grounding still apply to every approximation.

The review dialog reuses its existing handlers above the assistant dock; native Tools remains a separate modal. That matrix checks local behavior; the later bounded Cloudflare live workflow has its own receipt. See [runtime setup](RUNTIME.md) and [verification](VERIFICATION.md).
