# Public repository and drawing reliability audit

Audited public `Advaita-G/nox-icehacks` main at `df80b2f` against the checked-out source, actual GitHub README, Actions results, deployed-runtime evidence and new drawing experiments. **Whole-product requirements coverage: changes needed.** Broader drawing recognition is not established as very reliable, and no experimental backend has been promoted.

## Repository and setup

- A clean tracked-source export passed `npm ci`, input-package `npm ci`, 237 baseline root tests, 110 input tests and both builds. Both lockfile dependency audits reported zero vulnerabilities. This is the observed audit result, not a permanent security guarantee.
- The new bounded intake/framing checks add two root regressions. The exact staged main source passed **239/239 root tests**, **110/110 input tests**, root typecheck and both builds. The existing large application-chunk warning remains.
- GitHub Actions at `df80b2f` failed before the job started: the owner's account is locked for a billing issue. [Observed check](https://github.com/Advaita-G/nox-icehacks/actions/runs/43677849234). Local success is not hosted CI success.
- Source review covered local/production API gates, provider transport, schema generation, scene/grounding validation, photo intake, reviewed edits, persistence, rendering startup, deployment exclusions and README/runtime claims. The anonymous app, configured access and working inference are distinct states.
- No dependency was added. Tokens/codes remain server-side. Model text is data, never executed; UI messages use text nodes. Existing request limits, cancellation, cookie access, validators, confirmation and physics timing guards remain intact.
- Scratch handoffs are now excluded from Git and deployment uploads. AVIF was incorrectly advertised as accepted; the docs now match JPEG/PNG/WebP intake. Uniform raster rejection does not reject faint but non-uniform drawings. Camera framing now recognizes named fixed ground with arbitrary model IDs rather than relying only on the literal ID `floor`.

## Actual new model experiments

A corpus was frozen before inference: house, labelled sphere/plank, chair, tree, character, car, abstract shapes on a table, blank image, essential fluid flow and a lever/pivot. Eight images were newly generated; two reuse the preserved generated test drawings. These are digital drawings, not physical camera photos or a population accuracy benchmark. Gold descriptions were not sent to the model.

There were **23 direct evaluation requests** across evolving contracts/models, with all outcomes retained: initial Gemma plans, a reasoning-enabled trial, Qwen comparisons, a twelve-request Qwen corpus/repeat run, and final Gemma checks. This is development evidence, not a success-rate claim for one fixed production version. The final low-cost comparison reached the account's hard quota and stopped without retry. A separate local app request then confirmed quota-blocked failure; it did not establish a successful live workflow.

The proposed smaller intermediate format moves ID binding, metric geometry conversion and declared support contact into deterministic code. Regression checks cover gabled convex geometry, thin rotated shapes, a sphere on a tilted board, support cycles/misses, source-specific provenance, invalid values and cancellation. **It is an experimental branch, not the deployed backend.**

Offline replay of unedited Qwen plans through the corrected compiler produced eight valid rigid scenes and one second of real solver execution each. This includes fixes to compiler frame normalization and reversed source-region corners. The blank plan remains invalid rather than being silently fabricated into geometry. Essential fluid flow now asks for explicit rigid-proxy agreement before inference in the candidate. These offline results are not fresh model calls. The lever result omitted a hinge; a contact-balanced lever does not establish the requested pinned-pivot behavior. Earlier outputs omitted features, misplaced decoration, ignored essential fluid intent, or timed out; those remain failures/limits.

The final Gemma generation trial asked an unnecessary depth question for the house and rejected the annotated sphere/plank without usable geometry. Thus the new generation contract has **not** passed its reliability acceptance criteria. More live validation and generation work are required; green numerical tests cannot substitute for this.

## Browser and rendering

Isolated text/DOM browser checks at 1280 px normal motion and 320 px reduced motion passed uniform-image rejection with zero interpretation requests, explicit-fluid clarification/decline with zero provider calls, exact saved-library/previous-scene retention, no horizontal overflow and no page errors. These used a credential-free fixture server and scripted speech; they do not prove fresh model or physical-device operation.

The controlled full photo/edit/run workflow **failed at rendering startup**, before a successful run/edit/persistence sequence. The exact recorded drawing plan compiled and validated, but the unchanged rendering guard kept physics paused at zero. On this host, headless M4/Metal frame intervals included repeated ~100 ms stalls even on an empty page; one app idle profile used about 10 ms of task time over 2.5 s with no layout/recalculation work. That narrows investigation but does not establish a root cause or a fix. A baseline probe briefly reported Running at zero; that is not solver-advancement acceptance. No timing limit was relaxed, and no screenshot/video/desktop capture was taken.
